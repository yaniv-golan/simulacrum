Use `npm run build` followed by `npm run preview` for a frozen local playtest. Record the page’s build identifier and follow the versioned [assessment protocols](../../assessments/protocol/F1.md). Automated and AI reviews are not human acceptance.

For an interaction report, use **Record an issue** in the left sidebar, then Start recording, reproduce, Stop recording and Save recording. The local JSON records build, checkpoint, timed actions and command results. It is a diagnostic timeline, not qualification replay. Nothing is uploaded by this local recorder.

## Remote setup

<!-- doc-review {"version":1,"fingerprint":"46027b07faf4c2b9610732c4bcac520a87e0b1db508c8cab7ca8cb7d1d2bf815","dependencies":"docs/development/.reviews/playtesting/remote-setup.json","dependencyDigest":"79b664a9a2177c4ce8d22f47e096d1fb7f3382a36c748a4dba9f80102b7fece4","disposition":"still accurate","rationale":"Recorded blueprint environments use the canonical geometry reader. Remote playtests can use `node scripts/playtest-server.mjs` with `PLAYTEST_PUBLIC_DIR` pointing at a frozen build, a separate private `PLAYTEST_DATA_DIR`, and a random `PLAYTEST_TOKEN` of at least 32 characters. The server binds loopback port 4180; expose it through an HTTPS tunnel and share `/join?token=...`. The invitation grants access to the workshop, not stored sessions. The player explicitly starts data recording and can send text or microphone feedback tied to a view/state anchor. Data capture records the project, programs, actions, UI/camera context and visible workshop observations at a target 10 Hz. It requests no screen permission. Pending uploads persist in the separate v2 IndexedDB outbox and retry with identity-checked receipts; keep the tab open until all are received. An optional tab-video checkbox is available only when the server explicitly enables it; it starts unchecked and requires a browser supporting tab sharing. Microphone use remains a separate opt-in. Canvas-only feedback screenshots are captured after rendering and are bounded to 1280 pixels wide and 512 KiB; unavailable images do not block comments. Server limits are 2 MB/event, 10 MB/media chunk and 1 GB/session; the browser stops capture if its offline queue reaches 100 MB. To review received evidence locally, run `node scripts/export-playtest.mjs <private-session-directory>` and open the resulting `review.html`. Remote usability recordings do not replace qualification evidence. The offline player supports play, pause and seek through observed geometry, camera and state, with linked feedback and optional media. It does not execute captured programs or reproduce browser pixels, materials, wires or DOM layout. Sampling can miss short transients; gaps and unfinished sessions are labelled explicitly. Raw events remain available and retained raw files are checked against their recorded hashes before export. Review indexes encoded events and reconstructs state on seek, instead of retaining every full snapshot. Capture finishes automatically at 95,000 events or a conservative 64 MiB event budget, reserving room for the final keyframe; the completion dialog explains the limit. Versioned keyframes and bounded context deltas are batched for at most one second; feedback receipts and the terminal event flush immediately. Recovery drains the old immutable upload queue and does not resume capture without fresh consent.

Node session creation publishes a flushed temporary directory atomically. A failed parent-directory sync keeps the v2 request identity for exact retry. Restart removes unpublished creation directories and preserves older incomplete metadata-only directories under private `.incomplete-*` names; a corrupt recording journal still fails closed. Rejoin after restarting the Node server.

Remote playtests show a receipt beside each submitted comment after the server acknowledges it. Finishing stops capture and waits for the final recording uploads before confirming that the session is saved and the tab can be closed.

The remote feedback bar stays the same size while recording. Data and any opted-in media uploads run automatically; routine queue counts are hidden. Upload problems remain visible, and Finish session confirms success only after all recording data is received.

The [server](../../scripts/playtest-server.mjs#implementation), [browser client](../../src/application/remote-playtest.mjs#implementation) and [exporter](../../scripts/export-playtest.mjs#implementation) own admission, upload and review behavior. Keep the data directory outside the served public directory. Do not commit invitation tokens or recordings.

These implementation links cover admission, capture and export code plus declared dependencies. They do not assert the contents of a served workshop build or a player’s uploaded recording; identify those separately for each playtest.

An unmounted capture view stops recording and input immediately. An upload already dispatched retains its existing bounded timeout and may acknowledge its durable outbox entry. Disposal starts no further uploads; a future mount recovers unsent entries.

## Cloudflare hosting
<!-- doc-review {"version":1,"fingerprint":"3bdac2103a61d7a8e1ce72ae1672ba45df8c8cc06195da3e2df6e610dbe612c4","dependencies":"docs/development/.reviews/playtesting/cloudflare-hosting.json","dependencyDigest":"56685c950d11677eccf2510b003042f3393d2d286b7cb0f4d983b824ce9ca037","disposition":"still accurate","rationale":"The build wrapper preserves the produced static assets and Vite configuration; Worker bindings, upload storage and hosting instructions are unchanged."} -->

The Cloudflare adapter serves the workshop and a private v2 capture API from one origin. Production uses `https://simulacrum.build`. Staging and production require separate Cloudflare accounts, credentials, R2 buckets and Durable Object namespaces. The invitation enables uploads to known sessions within its generation; it does not grant recording reads. A separate admin bearer controls export and deletion. Cookies are signed, host-only, Secure and expire after seven days. Rotate the invitation generation to revoke cookies. Preserve the signing secret across code deployments.

[The Worker](../../scripts/playtest/worker.mjs#implementation) owns HTTP authentication, exact-origin admission and static-asset access. [The capture store](../../scripts/playtest/cloud-store.mjs#implementation) owns SQLite session/receipt metadata and private R2 payloads. The fixed `capture-v2` object name persists across versions. Protocol v2 acknowledges an upload only after its immutable R2 object and durable receipt exist. Retries with different bytes conflict. Deletion overwrites all reserved keys with permanent zero-byte markers before releasing payload capacity; never configure a lifecycle that deletes those markers. Cleanup retries through alarms and independent five-minute reconciliation. Provider outage leaves deletion pending and charged. Live deletion does not promise removal from provider backups or downloaded exports.

Limits are 20 retained sessions, 1 GiB per session, 20 GiB aggregate payload accounting and an 8 GiB lifetime metadata ledger. Cloud accounting includes 4 KiB per upload pointer. Human sessions expire after 30 days. Synthetic runs reserve payload, session slots and lifetime metadata before publication, expire after two hours and clean up only their own recordings. Repeated verification does not clear human sessions. Body readers admit at most two uploads, enforce byte limits and idle/total deadlines, and reject overload rather than buffering a queue. The retained Node adapter uses the same pre-read admission bound while retaining its filesystem accounting. Storage response deadlines retain the occupied admission slot until the underlying operation settles; new writes fail closed during an unresolved storage timeout.

The [v2 outbox](../../src/application/capture-outbox.mjs#implementation) uses its own IndexedDB database. Payload removal and an identity-checked acknowledgment commit together. Other tabs reconcile durable receipt state, so closing the uploading tab does not lose acknowledgment evidence. Terminal failures preserve bytes and suspend every queued upload for that session. Other sessions continue. The saved-recording picker targets retry, local discard and server-deletion requests without requiring a session ID. Local payloads are bounded to 100 MiB and metadata to 16 MiB. Browser permissions are always explicit; tab selection is the browser picker's choice, not proof that the user chose this workshop.

Run `npm run build`, then `npm run playtest:local` for local Workers development. Put synthetic `INVITATION_TOKEN`, `COOKIE_SECRET` and `ADMIN_TOKEN` values of at least 32 characters in an ignored `.dev.vars` file. The checked Wrangler configuration is local-only; it contains no real account IDs or production bindings. Do not invoke an unconfigured remote deployment. Local Workers testing uses emulated SQLite/R2. `verify-cloud-playtest` and `verify-remote-playtest` execute the same real-browser recording flow against cloud and Node adapters; `verify-cloud-runtime` exercises workerd without media permissions.

For hosted evidence, set `PLAYTEST_ADMIN_TOKEN` in the process environment and run `npm run playtest:download -- <https-origin> <session-id> <new-private-directory>`. The [downloader](../../scripts/playtest/download.mjs#implementation) reads a fixed journal cutoff, checks every payload hash and creates the existing local review layout. Exact event bytes are retained as `event-<sequence>.json` with their byte count and hash in the derived journal. Then run `node scripts/export-playtest.mjs <private-session-directory>`. Missing/corrupt bytes fail the export. A session-end event does not prove continuous recording or delivery of every final callback; the review says completion is not proven.

## Release operations

[Release policy](../../scripts/playtest/release-policy.json) names the initial `v2` release branch. The [shared release tool](../../scripts/playtest/release.mjs#implementation) freezes selected working-tree inputs, runs release verification in an isolated private copy and builds one package. `npm run release:prepare -- .release-private/<new-name>` accepts modified/untracked source without committing it. It rejects input drift and keeps the source copy outside public artifacts. The package manifest binds the actual Worker/assets bytes, source digest and capture protocol. Expired or altered packages cannot be promoted normally.

The [GitHub release workflow](../../.github/workflows/ci.yml) routes eligible release-branch pushes through one frozen preparation/verification job; PRs and other events retain independent automated/browser jobs. The always-evaluated `verification` aggregate rejects failures, cancellation and unexpected skips before staging admission. Configure branch protection to require this aggregate; repository settings must be verified separately. The package includes format checks and the full verification result. Package admission verifies the integrity-bound automation envelope, complete phase/check receipts and matching source, build, runtime and payload identities; missing or failed automation blocks publication, including recovery. Pending human acceptance stays separate. Its assets are the verified build; the Worker bundle is produced from the same unchanged frozen source, with deployed-bundle execution checked by hosted smoke. Local execution of the bundled Worker is not claimed. Production uses the separate [manual dispatch](../../.github/workflows/deploy-production.yml), selecting a successful release run ID and exact artifact digest and expected production predecessor version at dispatch. Both preflight and atomic admission reject a changed predecessor, including a newer local publication. The dispatcher validates repository, workflow, branch, source and staging evidence; a push or staging success alone never updates production. Configure GitHub staging/production environment deployment-branch restrictions for the trusted release branch before enabling either publisher. Queued staging jobs recheck workflow run order before mutation; an older run cannot replace a newer successful release. Publication also requires enough remaining synthetic reservation lifetime for verification and cleanup. The production dispatch file must be present on the repository's default branch to be selectable; check that setup explicitly without renaming branches.

Each environment needs an independently provisioned release-control Worker with the [publisher coordinator](../../scripts/playtest/release-control.mjs#implementation). Every supported publisher acquires its durable owner record before mutating that environment. Competing publishers fail without changing it. Ownership never expires automatically. Local commands additionally pause and later restore the matching GitHub deployment variable. On a lost response, crash, failed verification or cleanup outage, ownership remains held: stop the old publisher, establish that its remote operations settled and revoke its token if it could resume, then reconcile the actual deployed version before manually completing recovery. Never unlock on elapsed time alone. Ordinary workshop releases must not redeploy or reset the coordinator.

Before enabling automation, provision distinct accounts and private buckets, fixed Durable Object bindings, coordinator credentials, domain/TLS and explicit observability settings. Keep Worker invocation logging, traces, Tail consumers and request-log exports disabled. The [deployment verifier](../../scripts/playtest/verify-deployment.mjs#implementation) fails closed when effective settings or account-isolation checks cannot be read or verified. It reads non-versioned logging configuration from Cloudflare’s script-settings endpoint separately from capture bindings. An explicit null observability value means disabled; missing fields, active Logpush or Tail consumers, and enabled or incomplete logging settings fail admission. Disable bucket lifecycle rules during provisioning; R2 creates an enabled multipart-abort rule by default. Real account configuration and browser canary checks require authorized staging access; local tests do not establish them.

Configure `STAGING_RELEASE_CONFIG` and `PRODUCTION_RELEASE_CONFIG` as nonsecret JSON repository variables with the environment's account ID, other account ID, Worker name, exact origin, coordinator URL, expected initial predecessor and reviewed `wrangler` configuration. Both configurations also require `captureNamespaceId` and an `isolationTargets` inventory: `authorization: "disposable-probes-only"` and `currentWorker`, `otherWorker`, `currentBucket`, `otherBucket`, each naming an independently provisioned, empty `simulacrum-isolation-*` probe in the corresponding account. Keep probe resources separate from capture resources. The verifier checks current-account Worker read/write and bucket read, plus explicit denial of other-account Worker read/write and bucket read/CORS write. Probe secrets are synthetic and removed after a permitted write; the probe bucket has an empty CORS policy. Repeat the matrix with each environment credential. These bounded capability tests supplement reviewed account scoping. Effective capture bindings must match the pinned R2 bucket, namespace and class before and after publication; the [five-minute Cron](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/schedules/methods/get/) must also be present. Production also needs its zone ID. Set `DEPLOY_STAGING_ENABLED` and `DEPLOY_PRODUCTION_ENABLED` to literal `true` only after bootstrap checks pass. Repository secret `RELEASE_READ_TOKEN` supplies a repository-scoped GitHub App or fine-grained token with Actions read and [Variables read](https://docs.github.com/en/rest/actions/variables#get-a-repository-variable) for live pause/provenance checks (the built-in workflow token is still used for artifact downloads). Repository secrets `STAGING_CONTROL_TOKEN` and `PRODUCTION_CONTROL_TOKEN` authorize the preflight coordinators; they do not contain Cloudflare deployment authority. Each matching GitHub environment supplies its own account-scoped `CLOUDFLARE_API_TOKEN` and `PLAYTEST_ADMIN_TOKEN`. Cloudflare requires Account Logs Edit (API Logs Write) even for reading Logpush jobs; Logs Read alone is insufficient. Production additionally requires Zone Logs Edit scoped to its zone. The production token must be able to inspect required zone logging settings; missing read permissions block publication rather than bypassing checks.

For a local deployment, `npm run release:deploy -- <private-release-directory> <private-config.json>` selects the exact package. Its configuration names `environment`, `accountId`, `otherAccountId`, `workerName`, `origin`, `coordinator`, `repository`, `expectedPredecessor`, `artifact`, `wranglerConfig` and, for production, the successful staging evidence file. Supply environment-specific Cloudflare/admin/control tokens and a GitHub token authorized to manage the pause variable. The tool preserves storage and runs post-deployment verification plus run-owned synthetic cleanup before releasing ownership. A failed deployment may already have changed code; it must be recovered explicitly, not retried with a new owner.

Keep the last successful v2-compatible package privately for rollback. Rollback must retain v2 routes, receipt semantics and create-only payload writes, use the same publisher exclusion, and preserve R2/SQLite, signing secrets, coordinator and custom domain. Never deploy a legacy-only backend over v2 sessions or perform destructive migrations during a code rollback. Set `CAPTURE_NEW_SESSIONS=false` to stop new sessions while existing uploads drain.

Authenticated export retries recognized connection or body-read failures at most three times within the existing 45-second per-read budget, with at most 15 seconds per attempt. HTTP errors, redirects, malformed JSON, identity errors and checksum mismatches remain terminal. Only complete authenticated payloads advance the export cursor.

Served-asset integrity requests the canonical `/` URL for packaged `index.html`, refuses redirects, and compares the complete response bytes with the package hash. Other assets retain their packaged paths.

Every publication runs real browser capture with active building/driving and written feedback, followed by final drain, identity-checked export and run-owned cleanup. The smoke workload lasts at least 60 seconds; setup, upload drain and cleanup add wall time. Final drain has a fixed two-minute deadline and requires zero durable pending uploads, zero queued bytes and both saved-session UI confirmations; continued progress does not extend the deadline. The report records drain duration. The [shared browser budget](../../scripts/playtest/release-policy.mjs#implementation) adds this allowance, a separate two-minute written-feedback receipt deadline, and three minutes for setup and verified export to the active capture duration. Local/GitHub publication and characterization use the same budget, and synthetic reservation admission includes it. This delivery deadline is not an endurance or throughput qualification. Smoke is not endurance evidence. There is no unconditional thirty-minute staging requirement.

The [experiment policy](../../scripts/playtest/experiments.mjs#implementation) supports `auto`, `full` and `bypass-expensive` through the private release config's `verification` object. GitHub manual dispatch exposes the same mode, reason and acknowledged-failure IDs. `auto` reuses compatible unexpired family receipts or runs missing experiments; `full` runs both expensive families at the supplied calibrated durations. `bypass-expensive` requires a reason and skips only endurance/capacity. It works before calibration exists and reports `NOT_RUN` plus an artifact/environment/actor/attempt-bound exception. Production needs its own deliberate exception; staging exceptions never become qualification passes. A known failed experiment requires its explicit failure ID acknowledgement, or a later matching real pass. Failure history is retained in the coordinator and private local evidence. [GitHub transport](../../scripts/playtest/experiment-transport.mjs#implementation) retrieves bounded successful release-workflow artifacts from the same repository and release branch. It checks provenance, receipt integrity and artifact replacement; forks and PR runs are excluded. Both workflows export allowlisted experiment receipts and numeric failure summaries even after failure. Owner credentials, raw captures, paths and freeform errors are excluded. Failed experiments remain authoritative in the coordinator; exported successes never erase them.

Normal qualification needs a measured profile: calibration evidence identity, browser version, workload limits (media byte rate, event rate and maximum chunk bytes), evidence maximum age, endurance duration and capacity duration. No measured default is shipped. The accepted numerical ranges are input bounds, not a claim that any candidate duration is equivalent: endurance accepts 360–1800 seconds, capacity 120–600 seconds. Characterize active recording and deliberately induced backlog/recovery faults before selecting the shortest justified profile. Until hosted calibration exists, use an explicitly authorized exception plus mandatory smoke; do not invent profile evidence. `verification.calibrationFile` must reference the private comparison report and its adjacent capture, capacity and corpus files. [Calibration admission](../../scripts/playtest/calibration-evidence.mjs#implementation) verifies their fingerprints, independent run identities, actual measurements and browser identity. The profile contains `calibration.review` with reviewer, `reviewedAt` and separate duration, age, workload and limitations rationales. Only measured 360/600/1800-second endurance choices are admitted; capacity is 120–600 seconds. Workload bounds cannot exceed the tested corpus distribution. Local releases read that adjacent directory directly. GitHub preflight and deployment each call the [private bundle retriever](../../scripts/playtest/calibration-bundle.mjs#implementation) before publisher admission. Set `verification.calibrationBundle` in both release configuration variables to `{ "url": "https://<private-host>/<immutable-version>/manifest.json", "sha256": "<manifest SHA-256>" }`, and provide repository secret `CALIBRATION_BUNDLE_TOKEN` with read-only access to that private endpoint. Each file request sends the bearer token; redirects, URL credentials/query strings, unsafe paths, oversized downloads and mismatched hashes fail closed. Files download into a private temporary directory and become available together only after integrity validation. The full calibration reader then validates the reviewed evidence before ownership is acquired. A repository-variable `calibrationFile` or corpus path cannot replace this retrieval in GitHub. Explicit bypass does not download a bundle and retains its other admission rules.

After characterization and explicit profile review, run `node scripts/playtest/calibration-bundle.mjs pack <private-profile.json> <private-comparison.json> .release-private/<new-bundle>`. This validates and exports only the comparison, nine capture reports, capacity report and corpus, retaining their relative paths. It prints the manifest digest. Provision those exact files at an authenticated private immutable directory; do not upload them as public GitHub artifacts or commit them. The profile's evidence hash and the bundle manifest hash are separate pins. Changing either requires a reviewed configuration update. Private hosting, token setup and a real hosted-run retrieval remain deployment prerequisites; local tests do not provision them.

Run the explicit [characterization tool](../../scripts/playtest/calibrate.mjs#implementation) with `node scripts/playtest/calibrate.mjs <private-staging-config> <new-private-directory>` only on authorized staging. It holds publisher ownership and runs one 30-minute baseline, two independent 6-minute captures, two independent 10-minute captures, and four 3-minute transport/recovery cases, followed by a 10-minute capacity measurement. Each case gets a fresh browser and a bounded synthetic reservation. The tool prints this work before ownership: 74 minutes of active capture plus 10 minutes of capacity, excluding setup/drain. This is a one-time characterization comparison, not an 84-minute staging gate. Ordinary releases retain the 60-second smoke and select only required calibrated experiments. The fault cases exercise withheld acknowledgements after real commits, the real request-abort deadline, periodic transport loss, and reload with durable uploads pending. Browser heap/DOM samples and prefix comparisons expose trends without claiming leak-free behavior. Output remains MEASURED_NOT_APPROVED until reviewed. Actual measurement failures persist to private recovery history and the publisher coordinator before ownership can be released; failed or uncertain persistence retains ownership. Successful intentional fault injections are not recorded as failures. Calibration admission validates observation cadence/coverage, numeric driving and distinct periodic-loss windows against the recorded capture interval. This tool is not a routine release prerequisite and never promotes a deployment.

[Experiment inputs](../../scripts/playtest/experiment-inputs.mjs#implementation) bind packaged bytes, verifier owners, dependencies/runtime and effective provider configuration. Endurance binds every packaged asset/backend byte and its audited verifier closure; its exact manifest reader scopes cover packaged assets, synthetic capture/export data and provenance-only source reads. Unreviewed source/import changes restore complete-source fallback. Capacity may reuse across client changes only when manifest-owned exact source/import scopes match and the new smoke remains inside the calibrated workload envelope. A changed audited reader, unknown input, browser/config drift or expired receipt requires new evidence; receipt registration alone never proves compatibility. Scope hashes require semantic review before refreshing, not automatic regeneration. Workload drift fails qualification rather than silently enlarging bounds.

Calibration uses [bounded capture samples](../../scripts/playtest/capture-samples.mjs#implementation): each case retains at most 128 event templates within 3 MiB and 32 media chunks within 24 MiB. Largest event and admitted media payloads are mandatory; remaining samples span the capture. Reports preserve complete measured wire-packet counts, mode-specific media-byte totals, timing and backlog observations. Corpus schema 3 binds each UUID run to its sample ranges, measured totals and maxima; admission compares these measurements to each independent capture report. The nine-case corpus stays below existing bundle bounds. Capacity sends rotating samples plus the largest retained event at the full measured event rate, and retains the maximum-chunk media stress. This is a conservative stress sample, not a claim that sampling preserves the full empirical distribution.

[Load verification](../../scripts/playtest/load.mjs#implementation) is independent of long capture: twenty upload clients use the [calibrated synthetic corpus](../../scripts/playtest/corpus.mjs#implementation), built after all nine captures, with its fingerprint, source/build/browser provenance and retained media/event samples from every case, shaped to 5 Mbps uplink and approximately 100 ms RTT. Each three-second client interval sends a rotating retained sample plus enough copies of the largest observed chunk to cover the highest observed media rate, and enough retained events to cover the highest event rate. This is a deliberately conservative stress workload, not a claim that every session produces the worst case continuously. Capacity is measured against that exact corpus and schedule; profile limits cannot exceed that tested envelope. It measures delivery latency/backlog, retries/timeouts and a separate concurrent pair of 10 MiB uploads. CPU/RSS describe the load-generator process, not Worker resources. Endurance separately validates ordered dense samples and final drain at its declared duration; five adjacent one-minute medians rising by more than 128 KiB each and more than 1 MiB overall fail. Short bursts that drain remain valid.

Reservation size follows selected work before publication: capacity retains twenty session slots and its full payload/lifetime-metadata budget; smoke/endurance-only plans reserve their smaller declared budgets. Preliminary drain returns fenced slots/bytes atomically to the held reservation; lifetime metadata stays charged. An abandoned reservation or insufficient remaining lifetime blocks admission. Skipping expensive experiments cannot bypass artifact integrity, automation, auth/account isolation, privacy/logging, ownership/predecessor checks, capture receipt/deletion safety, smoke/export or cleanup. Failed verification/cleanup retains ownership for explicit recovery; deployed bytes alone do not imply qualification.

Use `node scripts/playtest/release.mjs rollback <previous-package> <private-config.json>` for an explicitly selected, previously verified production package. The production dispatch also has an explicit compatible-rollback mode taking a previous successful production run. For an interrupted local publisher, after stopping it and establishing remote quiescence, use `node scripts/playtest/release.mjs recover <selected-fresh-package> <private-config.json> <private-owner-file> --publisher-stopped`. Supply the actually deployed predecessor and the original owner record. This supports first-staging recovery without any previous production package, reuses an existing owner file, and can restore code while the currently deployed capture admin API is broken. Explicit recovery and compatible rollback keep package, coordinator, predecessor and provider binding checks, restore code first, then clean any known abandoned reservation and acquire verification capacity. They retain ownership if subsequent verification or cleanup fails; restoration alone is not a successful release. For a previously verified production rollback package use `recover-rollback` instead. All normal exceptions after reservation trigger run-owned cleanup; temporary raw exports and screenshots are purged on success and failure. Numeric outbox/workload failure diagnostics and resolved-failure records remain private and artifact-bound for diagnosis. A process kill or lost reservation response is recovered through the retained owner record or the two-hour synthetic expiry and Cron; local private remnants from a killed process must be removed during operator recovery. This reuses ownership; the flag is an operator attestation, not automatic proof that a remote operation stopped. Do not use it while the old process or credential can still mutate production.

Data capture uses `recordingMode: "data"` and `captureSchema: 1` in session and qualification evidence. Existing video calibration cannot authorize data capture. Local diagnostic video can be enabled with `PLAYTEST_OPTIONAL_VIDEO=true`; browser qualification selects it explicitly with `PLAYTEST_RECORDING_MODE=video`. Worker `CAPTURE_OPTIONAL_VIDEO` defaults to `false`. Publication with optional video enabled fails closed until qualification covers both offered modes; single-mode evidence is insufficient.

Data-mode capacity characterization retains actual voice-note samples, rates and maximum chunks, plus a separate maximum-admitted voice upload test. Data sessions reject screen uploads before reading their body; existing video sessions can still drain when new optional video is disabled. New downloads mark raw-event evidence as required. Older journals without raw files remain reviewable with an explicit provenance limitation. Keyframes occur at least every five seconds or 256 events, whichever comes first.
