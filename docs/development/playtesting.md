Use `npm run build` followed by `npm run preview` for a frozen local playtest. Record the page’s build identifier and follow the versioned [assessment protocols](../../assessments/protocol/F1.md). Automated and AI reviews are not human acceptance.

For an interaction report, use **Record an issue** in the left sidebar, then Start recording, reproduce, Stop recording and Save recording. The local JSON records build, checkpoint, timed actions and command results. It is a diagnostic timeline, not qualification replay. Nothing is uploaded by this local recorder.

The [workshop application](../../src/application/workshop-app.mjs#source)
reports JavaScript view preparation separately as `viewRenderMs`. Place/connect/run
reflection receipts wait for a cursor-keyed render-submission completion recorded
by the [workshop view](../../src/presentation/workshop-view.mjs#source).
The diagnostic field `completedDraw` marks return from the renderer call, not GPU
completion, compositor presentation or physical display latency. `run-first-tick`
remains a separate simulation-reflection measurement. Compare identical before/after
workloads before claiming a latency improvement.
Current reflection samples identify `cursor-keyed-render-submission-v1`; first-tick
samples identify `completed-first-tick-v1`. F2 protocol version 2 requires these
endpoints and completed outcomes. Historical unlabeled or two-animation-frame
samples are not interchangeable with this protocol. A five-second timer records
`timeout` when no eligible draw arrives; disposal records `cancelled`. These
incomplete samples retain null latency and cannot qualify as successful measurements.

Remote playtests can use `node scripts/playtest-server.mjs` with `PLAYTEST_PUBLIC_DIR` pointing at a frozen build, a separate private `PLAYTEST_DATA_DIR`, and a random `PLAYTEST_TOKEN` of at least 32 characters. The server binds loopback port 4180; expose it through an HTTPS tunnel and share `/join?token=...`. The invitation grants access to the workshop, not stored sessions. The player explicitly starts data recording. Give feedback is available before, during and after recording, and never starts capture by itself. Data capture records the project, programs, actions, UI/camera context and visible workshop observations at a target 10 Hz. Recording admits at most 512 machine parts; larger workshops remain saveable, with event byte limits enforced independently. It requests no screen permission. Pending uploads persist in the separate v2 IndexedDB outbox and retry in durable insertion order with identity-checked receipts; keep the tab open until all are received. An optional tab-video checkbox is available only when the server explicitly enables it; it starts unchecked and requires a browser supporting tab sharing. Microphone comments require a separate opt-in; the workshop image and the project/workshop-context snapshot are attached by default on a fresh draft, disclosed above the composer, and can be unticked before Send. Canvas-only images are captured after rendering and bounded to 1280 pixels wide and 512 KiB; unavailable images do not block text feedback. Server limits are 2 MB/event, 10 MB/media chunk and 1 GB/session; the browser stops capture if its offline queue reaches 100 MB. To review received evidence locally, run `node scripts/export-playtest.mjs <private-session-directory>` and open the resulting `review.html`. Remote usability recordings do not replace qualification evidence. The offline player supports play, pause and seek through observed geometry, camera and state, with linked feedback and optional media. It does not execute captured programs or reproduce browser pixels, materials, wires or DOM layout. Sampling can miss short transients; gaps and unfinished sessions are labelled explicitly. Raw events remain available and retained raw files are checked against their recorded hashes before export. Review retains compressed packets plus event locators and reconstructs state on seek, with only one expanded packet and one private reconstructed context cached. Forward seeks within the same valid chain resume that context; backward seeks and new independent frames restart reconstruction. Returned contexts are copied so review callers cannot alter later seeks. Entire packets may arrive out of order; interleaved sequence ranges are rejected before replay traversal to prevent repeated packet expansion. Capture finishes automatically at 95,000 events or a 384 MiB encoded-event or 112 MiB transferred-packet budget, reserving 4 MiB for final packets; the completion dialog explains the limit. Versioned keyframes and bounded context deltas are batched for at most one second; the terminal event flushes immediately; independent feedback uses its own submission endpoint and receipts. Recovery drains the old immutable upload queue and does not resume capture without fresh consent.

Canvas-only feedback uses the currently visible workshop image: the retained optical
canvas while machine camera view is active, and a fresh orbit render after returning
to workshop view. An unavailable active camera image reports unavailable rather than
substituting the hidden orbit view. The [screenshot owner](../../src/presentation/workshop-screenshot.mjs#symbol=captureWorkshopScreenshot)
copies the displayed pixels without requesting another camera exposure.

Node session creation publishes a flushed temporary directory atomically. A failed parent-directory sync keeps the v2 request identity for exact retry. Restart removes unpublished creation directories and preserves older incomplete metadata-only directories under private `.incomplete-*` names; a corrupt recording journal still fails closed. Rejoin after restarting the Node server.

Give feedback opens one recoverable local draft, owned by one editor through a Web Lock. Closing, Escape and reload retain a draft that has text or voice when IndexedDB is available; a draft holding only the default captures is dropped on close and recaptured on the next open. If durable storage or editor coordination is unavailable, the fallback explicitly offers text only and does not promise reload recovery. Recovery mounts before remote configuration so a disconnected reload can still expose saved work. Drafts become immutable submissions only through Send feedback. Text is limited to 10,000 Unicode characters; one optional voice clip is limited to 60 seconds and 2 MiB, context to 256 KiB, image to 512 KiB and the complete serialized envelope to 4 MiB. Voice chunks stay local until the player explicitly sends; playback and removal are available before sending.

The [feedback client](../../src/application/feedback-client.mjs#implementation) keeps recording completion separate from feedback delivery. Finish session stops capture and microphone input immediately, then offers Send, Keep draft or Discard for unsent feedback. A recording receipt never claims that a draft was sent. The application mounts feedback and recording controls in the existing workshop footer supplied by the view. The controls remain in layout rather than over the canvas or inspector. It keeps Give feedback and its waiting/attention/draft status reachable even when recording is unavailable; recording controls and active or unresolved recording state appear only when relevant. The compatible invitation opens dismissible consent setup and Start recording reopens it; history and saved-recording management are secondary disclosures. Recording setup, project information and session completion dismiss through the shared top-right × from [dialog close](../../src/presentation/dialog-close.mjs); Retry uploads stays an explicit action and closing the completion dialog does not cancel delivery. Exact-byte retries retain submission identity. Only an identity- and digest-checked durable server receipt earns “Sent to Yaniv for review.” This confirms receipt, not that a person has read it or promised a fix. Permanent rejection preserves bytes for explicit recovery; local discard prevents later queued dispatch and cannot recall a request already sent.

The [feedback store](../../src/application/feedback-store.mjs#implementation) has a separate 32 MiB local budget. Freezing a draft and removing its editable version is one transaction. Receipt acceptance commits durably; received local copies remain available for review and explicit local removal. Revisions fence stale attachment writes. Image and context capture their own timestamps and optional recording references when attached (by default at open, or by a later tick). The [feedback context owner](../../src/application/feedback-context.mjs#symbol=captureFeedbackContext) reads the saved authored project, including authored programs, and current workshop UI state when the default context capture or a later tick attaches it; the disclosure names programs explicitly. It does not read the replay checkpoint, native physics snapshot or derived replay configuration. The 256 KiB context limit still applies to those authored/UI bytes. Text-only feedback includes neither this context nor a recording identity.

The [capture gate](../../src/application/feedback-capture-gate.mjs#implementation) suppresses opted-in tab video in participating supported-build tabs before protected feedback content appears. Closing feedback can resume capture only while recording remains requested. Failed suppression keeps the protected content hidden. An old tab without this coordination protocol cannot be detected; setup therefore instructs players to close older workshop tabs. Unsupported coordination disables this build’s optional tab video. Screen recordings use sealed segments with encoder-measured media durations. The [duration reader](../../src/application/capture-media-duration.mjs#implementation) never substitutes wall time; feedback pauses, unknown duration and missing segments appear as unavailable video in review. Data capture remains continuous and does not include feedback text or voice.

Both adapters expose POST /api/playtest/feedback/v1/submission and advertise feedback protocol 1 independently of capture protocol 2. The [Node feedback store](../../scripts/playtest/feedback-node.mjs#implementation) and [cloud feedback store](../../scripts/playtest/feedback-cloud.mjs#implementation) publish exact envelope bytes with durable receipts and reject conflicting reuse of an identity. The default independent feedback payload budget is 128 MiB, configurable through PLAYTEST_FEEDBACK_STORAGE_BYTES on Node or FEEDBACK_STORAGE_BYTES on Workers. PLAYTEST_FEEDBACK_ENABLED=false or FEEDBACK_ENABLED=false disables new feedback admission. Invitation authentication and origin checks apply; recording references must belong to that invitation. Cloud payloads remain private R2 objects, with only metadata in SQLite.

Admin bearer access lists /admin/playtest/feedback (limit and after pagination, optional sessionId), exports /admin/playtest/feedback/:id/export, and deletes through POST /admin/playtest/feedback/:id/delete. Linked recording cleanup also removes linked feedback; standalone feedback has its own deletion path. The [feedback downloader](../../scripts/playtest/download-feedback.mjs#implementation) validates receipt hashes and writes private feedback.json files, either independently or by explicit append to a matching downloaded capture. The existing exporter accepts that file and produces review.html with the submitted text, selected attachments and their references. Retained local copies and downloaded exports are separate from server deletion.

The [server](../../scripts/playtest-server.mjs#implementation), [browser client](../../src/application/remote-playtest.mjs#implementation) and [exporter](../../scripts/export-playtest.mjs#implementation) own admission, upload and review behavior. Keep the data directory outside the served public directory. Do not commit invitation tokens or recordings.

These implementation links cover admission, capture and export code plus declared dependencies. They do not assert the contents of a served workshop build or a player’s uploaded recording; identify those separately for each playtest.

An unmounted capture view stops recording and input immediately. An upload already dispatched retains its existing bounded timeout and may acknowledge its durable outbox entry. Disposal starts no further uploads; a future mount recovers unsent entries.

The Cloudflare adapter serves the workshop and a private v2 capture API from one origin. Production uses `https://simulacrum.build`. Staging and production require separate Cloudflare accounts, credentials, R2 buckets and Durable Object namespaces. The invitation enables uploads to known sessions within its generation; it does not grant recording reads. A separate admin bearer controls export and deletion. Cookies are signed, host-only, Secure and expire after seven days. Rotate the invitation generation to revoke cookies. Preserve the signing secret across code deployments.

[The Worker](../../scripts/playtest/worker.mjs#implementation) owns HTTP authentication, exact-origin admission and static-asset access. [The capture store](../../scripts/playtest/cloud-store.mjs#implementation) owns SQLite session/receipt metadata and private R2 payloads. The fixed `capture-v2` object name persists across versions. Protocol v2 acknowledges an upload only after its immutable R2 object and durable receipt exist. Retries with different bytes conflict. Deletion overwrites all reserved keys with permanent zero-byte markers before releasing payload capacity; never configure a lifecycle that deletes those markers. Cleanup retries through alarms and independent five-minute reconciliation. Reconciliation rearms overdue alarm timestamps immediately, leaves imminent future alarms in place, and schedules missing or distant alarms within one second. Provider outage leaves deletion pending and charged. Live deletion does not promise removal from provider backups or downloaded exports.

Limits are 20 retained sessions, 1 GiB per session, 20 GiB aggregate payload accounting and an 8 GiB lifetime metadata ledger. Cloud accounting includes 4 KiB per upload pointer. Human sessions expire after 30 days. Synthetic runs reserve payload, session slots and lifetime metadata before publication, expire after two hours and clean up only their own recordings and feedback. The run-specific synthetic status endpoint reports pending counts and charged bytes separately for both; cleanup succeeds only when all four values reach zero. A failed feedback deletion fence remains pending and charged even after recording deletion completes. Repeated verification does not clear human sessions. Hosted readers enforce idle/total deadlines and reject overload rather than buffering a queue. The retained Node adapter keeps its two-upload pre-read admission bound and filesystem accounting.

Hosted upload admission allows 32 concurrent requests within a shared 20 MiB wire-body reservation. Small media and event requests share this budget; two maximum-size 10 MiB media requests consume it completely. A valid declared Content-Length reserves its exact size and is enforced while reading; requests without it reserve the route maximum. These are wire-byte limits, not a total heap guarantee. Parsed event payloads do not survive across storage awaits, and event hashing reuses the raw digest. Upload reservations and the 32-operation storage lane remain charged until outstanding provider operations settle even after a response timeout. Export/control has a separate 2-operation lane. Cleanup uses up to eight concurrent zero-byte deletion-marker writes in a dedicated lane; all lanes honor the outage circuit and remain occupied until provider settlement. Cleanup settles each batch and preserves successful fences before retrying failures. It starts at most 100 keys per alarm and starts no further batch after ten seconds; payload capacity returns only after every reserved key is fenced. New durable random object reservations use checksum-verified conditional PUT first, while previous pending reservations retain GET/reconciliation and deletion fencing. No path unconditionally overwrites recording payloads.

The [v2 outbox](../../src/application/capture-outbox.mjs#implementation) uses its own IndexedDB database. Payload removal and an identity-checked acknowledgment commit together. Other tabs reconcile durable receipt state, so closing the uploading tab does not lose acknowledgment evidence. Terminal failures preserve bytes and suspend every queued upload for that session. Other sessions continue. The saved-recording picker targets retry, local discard and server-deletion requests without requiring a session ID. Local payloads are bounded to 100 MiB and metadata to 16 MiB. Browser permissions are always explicit; tab selection is the browser picker's choice, not proof that the user chose this workshop.

Run `npm run build`, then `npm run playtest:local` for local Workers development. Put synthetic `INVITATION_TOKEN`, `COOKIE_SECRET` and `ADMIN_TOKEN` values of at least 32 characters in an ignored `.dev.vars` file. The checked Wrangler configuration is local-only; it contains no real account IDs or production bindings. Do not invoke an unconfigured remote deployment. Local Workers testing uses emulated SQLite/R2. `verify-cloud-playtest` and `verify-remote-playtest` execute the same real-browser recording flow against cloud and Node adapters; `verify-cloud-runtime` exercises workerd without media permissions.

For hosted evidence, set `PLAYTEST_ADMIN_TOKEN` in the process environment and run `npm run playtest:download -- <https-origin> <session-id> <new-private-directory>`. The [downloader](../../scripts/playtest/download.mjs#implementation) reads a fixed journal cutoff, downloads at most two payloads concurrently, checks every payload hash and creates the existing local review layout. Each group settles before another starts; verified raw files and journal rows retain sequence order. A failed group stops the export after its active reads settle. Exact event bytes are retained as `event-<sequence>.json` with their byte count and hash in the derived journal. Then run `node scripts/export-playtest.mjs <private-session-directory>`. Missing/corrupt bytes fail the export. A session-end event does not prove continuous recording or delivery of every final callback; the review says completion is not proven.

Recording supports a subset of admitted workshops: at most 512 machine parts,
including scenes with up to 32 authored objects, and the unchanged 2 MiB event limit.
[Recording admission](../../src/application/recording-admission.mjs#source) rejects
oversized initial observations and encoded updates before capture claims support.
Large controller/checkpoint payloads can still hit byte limits and stop capture

retains legacy preset interpretation and individual scene IDs/transforms; it does
not execute or convert historical opaque checkpoints.

[Release policy](../../scripts/playtest/release-policy.json) names `main` as the release branch. It rejects input drift and keeps the source copy outside public artifacts. The package manifest binds the actual Worker/assets bytes, source digest and capture protocol. Expired or altered packages cannot be promoted normally.

The [GitHub release workflow](../../.github/workflows/ci.yml) routes an explicit `workflow_dispatch` on the release branch through one frozen preparation/verification job; pushes to the release branch, PRs and scheduled runs take the independent automated/browser jobs under the registered hosted profile (`hostProfiles` in the manifest), which never produce a release package and are never selected as release runs by the publisher. The always-evaluated `verification` aggregate rejects failures, cancellation and unexpected skips before staging admission. Staging admission is skipped while `DEPLOY_STAGING_ENABLED` is not `true`; package verification still runs, and the publisher independently rejects a paused deployment. Configure branch protection to require this aggregate; repository settings must be verified separately. The package includes format checks and the full verification result. Package admission verifies the integrity-bound automation envelope, complete phase/check receipts and matching source, build, runtime and payload identities; missing or failed automation blocks publication, including recovery. Pending human acceptance stays separate. Its assets are the verified build; the Worker bundle is produced from the same unchanged frozen source, with deployed-bundle execution checked by hosted smoke. Local execution of the bundled Worker is not claimed. Production uses the separate [manual dispatch](../../.github/workflows/deploy-production.yml), selecting a successful release run ID and exact artifact digest and expected production predecessor version at dispatch. Both preflight and atomic admission reject a changed predecessor, including a newer local publication. The dispatcher validates repository, workflow, branch, source and staging evidence; a push or staging success alone never updates production. Configure GitHub staging/production environment deployment-branch restrictions for the trusted release branch before enabling either publisher. Queued staging jobs recheck workflow run order before mutation; an older run cannot replace a newer successful release. Publication also requires enough remaining synthetic reservation lifetime for verification and cleanup. The production dispatch file must be present on the repository's default branch to be selectable; check that setup explicitly without renaming branches.

Each environment needs an independently provisioned release-control Worker with the [publisher coordinator](../../scripts/playtest/release-control.mjs#implementation). Every supported publisher acquires its durable owner record before mutating that environment. Competing publishers fail without changing it. Ownership never expires automatically. Local commands additionally pause and later restore the matching GitHub deployment variable. Never unlock on elapsed time alone. Ordinary workshop releases must not redeploy or reset the coordinator.

Run the explicit [characterization tool](../../scripts/playtest/calibrate.mjs#implementation) with `node scripts/playtest/calibrate.mjs <private-staging-config> <new-private-directory>` only on authorized staging. It holds publisher ownership and runs one 30-minute baseline, two independent 6-minute captures, two independent 10-minute captures, and four 3-minute transport/recovery cases, followed by a 10-minute capacity measurement. Each case gets a fresh browser and a bounded synthetic reservation. The child deadline budgets one minute for setup, two minutes each for feedback delivery and final drain, and fifteen minutes for checksum export and replay indexing after the declared capture. The archive allowance is independent of delivery limits; a measured 30-minute archive needed over four minutes just for verified downloads. Private phase timings distinguish capture, feedback, completion, export, indexing and screenshot/report work. The tool prints this work before ownership: 74 minutes of active capture plus 10 minutes of capacity, excluding setup/drain. This is a one-time characterization comparison, not an 84-minute staging gate. Ordinary releases retain the 60-second smoke and select only required calibrated experiments. The fault cases exercise withheld acknowledgements after real commits, the real request-abort deadline, periodic transport loss, and reload with durable uploads pending. Browser heap/DOM samples and prefix comparisons expose trends without claiming leak-free behavior. Output remains MEASURED_NOT_APPROVED until reviewed. Actual measurement failures persist to private recovery history and the publisher coordinator before ownership can be released; failed or uncertain persistence retains ownership. Successful intentional fault injections are not recorded as failures. Calibration admission validates observation cadence/coverage, numeric driving and distinct periodic-loss windows against the recorded capture interval. This tool is not a routine release prerequisite and never promotes a deployment.

Unreviewed source/import changes restore complete-source fallback. Calibration uses [bounded capture samples](../../scripts/playtest/capture-samples.mjs#implementation): each case retains at most 128 event templates within 3 MiB and 32 media chunks within 24 MiB. Largest event and admitted media payloads are mandatory; remaining samples span the capture. Reports preserve complete measured wire-packet counts, mode-specific media-byte totals, timing and backlog observations. Corpus schema 3 binds each UUID run to its sample ranges, measured totals and maxima; admission compares these measurements to each independent capture report. The nine-case corpus stays below existing bundle bounds. Capacity sends rotating samples plus the largest retained event at the full measured event rate, and retains the maximum-chunk media stress. This is a conservative stress sample, not a claim that sampling preserves the full empirical distribution.

[Load verification](../../scripts/playtest/load.mjs#implementation) is independent of long capture: twenty upload clients use the [calibrated synthetic corpus](../../scripts/playtest/corpus.mjs#implementation), built after all nine captures, with its fingerprint, source/build/browser provenance and retained media/event samples from every case, shaped to 5 Mbps uplink and approximately 100 ms RTT. Each three-second client interval sends a rotating retained sample plus enough copies of the largest observed chunk to cover the highest observed media rate, and enough retained events to cover the highest event rate. This is a deliberately conservative stress workload, not a claim that every session produces the worst case continuously. Capacity is measured against that exact corpus and schedule; profile limits cannot exceed that tested envelope. It measures delivery latency/backlog, retries/timeouts and a separate concurrent pair of 10 MiB uploads. CPU/RSS describe the load-generator process, not Worker resources. Endurance separately validates ordered dense samples and final drain at its declared duration; five adjacent one-minute medians rising by more than 128 KiB each and more than 1 MiB overall fail. Short bursts that drain remain valid.

Reservation size follows selected work before publication: capacity retains twenty session slots and its full payload/lifetime-metadata budget; smoke/endurance-only plans reserve their smaller declared budgets. Preliminary drain returns fenced slots/bytes atomically to the held reservation; lifetime metadata stays charged. An abandoned reservation or insufficient remaining lifetime blocks admission. Skipping expensive experiments cannot bypass artifact integrity, automation, auth/account isolation, privacy/logging, ownership/predecessor checks, capture receipt/deletion safety, smoke/export or cleanup. Capacity cleanup failure preserves any completed measurement and both failure causes; it never converts a failed cleanup into success. Failed verification/cleanup retains ownership for explicit recovery; deployed bytes alone do not imply qualification.

Standalone feedback protocol 1 capacity remains unqualified until hosted measurements validate its envelope transport, receipt processing and independent storage budget. Fully qualified releases therefore require feedback to be explicitly disabled with FEEDBACK_ENABLED: "false" in the validated Worker configuration actually deployed. Feedback-enabled publication remains available only through the existing explicitly authorized experimental exception, with source-bound automated verification and mandatory live smoke and cleanup checks. Profile claims cannot override the deployed setting. Data sessions reject screen uploads before reading their body; existing video sessions can still drain when new optional video is disabled. New downloads mark raw-event evidence as required. Older journals without raw files remain reviewable with an explicit provenance limitation. Keyframes occur at least every five seconds or 256 events, whichever comes first.

Capture batches of at least 4 KiB use application-level canonical gzip (level 6, fixed timestamp; earlier level-1 packets remain readable) in a JSON base64 envelope only when the complete envelope saves at least 15 percent. The same 2 MiB wire limit and a separate 2 MiB expanded-packet limit apply. Producers reserve 4 MiB below the 112 MiB wire and 384 MiB encoded-event session budgets for terminal packets; the independent 100 MiB offline outbox remains unchanged. Review accepts up to 128 MiB of wire records and 384 MiB of encoded events, retaining compressed packets and expanding one packet at a time. Legacy fully expanded review retains its separate 256 MiB ceiling. Both adapters validate envelope types, encoding and declared expansion bounds before storage, without decompressing opaque event contents. Receipts attest exact durable wire bytes, not replay validity. Corrupt compressed contents inside a well-formed envelope can be stored; export/review rejects them through bounded decoding before treating them as valid replay. Outbox retries and receipts retain the exact compressed envelope bytes. Offline review validates the same encoding before applying context deltas. Media is not recompressed. The pinned [packet codec](../../src/application/capture-packet.mjs#implementation) rejects noncanonical headers, concatenated members, damaged/truncated streams, excessive expansion and unsupported encodings. Qualification measures the actual encoded packets, not decompressed byte estimates.
