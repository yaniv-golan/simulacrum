# F5 player-owned browser-agent assessment protocol

Use a player with their own browser agent. Record the participant identifier, prior exposure, running application's displayed build identifier, browser and agent versions, and the machine used. Prepare a machine with a failure whose cause is independently known to the assessor; do not reveal that cause to the player or agent.

While remaining in the game, the player asks their agent why the machine is not working. Preserve the question, tool interactions and answer. Pass requires an actionable answer that correctly identifies the independently known cause and a repair available through the player's ordinary interface. Verify the suggested repair on the machine. Record whether the player left the game or received assessor help; either invalidates this assessment, which is then recorded as `incomplete` unless a criterion had already been judged and not met. Do not substitute an engine-internal diagnostic or an agent controlled by the assessor. A session that ended before any criterion could be judged is recorded with the `incomplete` verdict and notes naming what was not observed; it supplies no verdict, so the latest complete session continues to govern and a bar with only incomplete sessions stays pending. A session in which any criterion was judged and not met — the time limit elapsed without the required result, an explicit non-acceptance, or an unresolved material complaint — is a fail even if it ended early.
